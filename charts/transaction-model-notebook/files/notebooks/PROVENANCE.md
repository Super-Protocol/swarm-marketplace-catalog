## The edits, by kind

### 1. The data is the tenant's, and nothing reaches the network

Upstream's `01` downloads the public IBM TabFormer corpus (~2.2 GB, 24.4M synthetic US card
transactions) from IBM Box and extracts it beside the checkout. That is replaced by
`tfm_workspace.load_transactions()`, which reads the dataset bound to the deployment — a
ClickHouse table served through the marketplace gatekeeper — or a `.csv`/`.parquet` extract the
tenant uploaded into `/workspace/data`.

Concretely, in `01_dataset_baseline.ipynb`:

- the **markdown** telling the reader to download the corpus is replaced with a description of
  what this deployment reads instead. It is the only cell replaced with prose of ours;
- the **download cell** is replaced by the binding, checkpoint and column-mapping description;
- the **`cudf.read_csv`** cell is replaced by `load_transactions()`, the coverage check and the
  fraud-label check.

`tfm_workspace.py` also renames the tenant's columns onto the names upstream's tokenizer
expects, derives upstream's `Year`/`Month`/`Day`/`Time` quartet from a single timestamp column,
casts `Amount` to a string (upstream's own code calls `.str.replace('$', …)` on it, which raises
on a numeric column), normalises the fraud label to upstream's `'Yes'`/`'No'` domain (upstream
reads it as `== 'Yes'`, which silently matches nothing on a 0/1 column), substitutes the
constant upstream's tokenizer would have produced for a field the extract does not carry, and
sorts by customer and time so the sequences read forwards. None of that is a change to a
notebook; it is a module the notebooks call.

### 2. The paths

Upstream keeps the corpus, the derived splits, the tokenised corpus, the embeddings, the
configuration, the training script and the checkpoint all under the checkout. Here:

- upstream's **code, configuration and checkpoint** are in the image at `/opt/tfm` — read-only,
  and named by the image digest in the deployment's evidence. `PROJECT_ROOT / "models/decoder-foundation-model"`
  becomes `tfm.MODEL_DIR`, and `sys.path.append(PROJECT_ROOT)` is unnecessary and removed;
- everything **derived** is written under `/workspace/derived` through `tfm.derived(...)`, which
  is the volume and the only thing that survives a pod restart;
- `03`'s `PYTHON = "/opt/venv/bin/python"` — the NeMo container's virtualenv — becomes
  `sys.executable`. This image has one environment and the kernel runs in it;
- stale `data/...` paths in prose are repointed at `/workspace/derived/...`.

### 3. The environment is in the image

Every `%pip install` is removed (`01`, `02`, `04` twice). The environment is installed at image
build time from a lock that pins all 62 wheels by sha256, so what the notebooks import is what
the deployment's evidence says it is. A package fetched after the pod starts is covered by
nothing.

### 4. The coverage check — added, with no counterpart upstream

This is the only *addition*, and it is the reason this listing can be honest about what it
sells.

The shipped checkpoint was pretrained with a fixed 6,251-token vocabulary that enumerates US
state abbreviations, 3-digit ZIP prefixes, a fixed list of merchant category codes, seven
dollar-amount buckets and customer indices 0–2999. Nothing upstream checks that the data being
tokenised has anything to do with that vocabulary — on a public corpus it always does. On a
tenant's own transactions it may not, and the failure is silent: every field tokenises to its
catch-all (`STATE_XX`, `MCC_-1`, `CAT_GENERAL`, a clipped `CUST_2999`), the model returns
512-dimensional embeddings, the UMAP looks like a UMAP and XGBoost reports an AUROC.

So `tfm_workspace.check_coverage()` measures the fraction of rows whose value is a token the
tokenizer actually has, per field, prints it, and raises below the deployment's floor. It runs
in `00_environment.ipynb`, in `01` when the data is loaded, and in `04` before the first
embedding is extracted — where it also asserts that the tokenizer's vocabulary size is exactly
the checkpoint's embedding-table height, so the ids cannot index the wrong table.

### 5. Stored outputs

Stripped. Upstream's notebooks ship clean already; this is asserted rather than assumed, because
an output computed from a corpus no deployment of this listing has would otherwise be published
inside its evidence snapshot.

## What was NOT changed

The tokenizer deep-dive, the GPT-2 comparison, the temporal split, the XGBoost baseline and its
hyperparameters, the corpus chunking, the NeMo AutoModel training invocation, the last-token
pooling, the UMAP projections and the three-way feature comparison in `05` are upstream's, cell
for cell. The numbers they produce are this deployment's data, not NVIDIA's.
