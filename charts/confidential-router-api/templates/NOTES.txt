{{ if eq .Values.billing.mode "disabled" }}
This deployment sells no credit: the console has no buy panel and a checkout is
refused. Credit arrives as a grant — an invitation code redeemed at sign-up, the
feedback offer, or `credits grant`. Set billing.mode=stripe with real credentials
to take payments.
{{- end }}
{{- if eq .Values.auth.magicLink.mailer "console" }}
Sign-in links are written to the API log, not sent:

  kubectl logs -n {{ .Release.Namespace }} deploy/{{ include "confidential-router-api.fullname" . }} | grep 'Magic link'
{{- end }}
{{- if .Values.auth.password.enabled }}
Email and password sign-in is on: anyone who can reach the console can create an
account there, with its own empty workspace and no credit. There is no password
reset — it would need the mail delivery this path exists to do without.
{{- end }}
{{- if .Values.invites.landingHostname }}
Invitation codes are handed out at {{ include "confidential-router-api.landingUrl" . }}, which is the
one origin besides the console allowed to look a code up from the browser.
{{- if not (or .Values.auth.adminEmails .Values.auth.adminEmailsExistingSecret) }}
Nobody can read how that campaign converts: auth.adminEmails is empty, so the
console's operator-only queries refuse everyone — and on a published cluster
space there is no exec to run `invites stats` through instead.
{{- end }}
{{- end }}
{{- if not (or .Values.analytics.posthog.projectKey .Values.analytics.posthog.existingSecret) }}
Product analytics is off: the console's events are accepted with 202 and dropped,
and so are the ones captured here. Set analytics.posthog.projectKey to record
them.
{{- end }}
{{- if .Values.externalEndpoints.enabled }}
The attested egress is on. An administrator can register a model endpoint living
in another deployment, and nothing is proxied to it until the gatekeeper beside
this API has verified its evidence, found its measurement on the trust list and
pinned its TLS leaf — then re-verified it every {{ .Values.externalEndpoints.reattestInterval }}, dropping it from
/v1/models the moment a check fails. Both lists live in the console's admin
section; neither is a chart value.

An upstream's API key is sealed with CR_API_SECRETS_KEY. Rotating that key does
not re-encrypt anything — every stored upstream key becomes unreadable and has to
be entered again.

This container changes what the deployment attests. For anyone pinning its
digest, shipping it is a re-pin rollout: pin the old digest and the new one,
deploy, then remove the old (ADR-003 §3).
{{- end }}
