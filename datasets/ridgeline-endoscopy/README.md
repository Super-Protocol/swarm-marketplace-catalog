# Ridgeline Endoscopy Partners — Colonoscopy Surveillance (US)

A synthetic eleven-site rural US gastroenterology network: 18,000 patients, a record going back
to 2016, an adenoma detection rate of **26%** — just over the accepted 25% floor — and a registry
with gaps in it that are declared, measured, and the most interesting thing about this corpus.

Everything here is generated by `datasets/gi-network-generator/` (`--network ridgeline`). No row,
no name and no sentence is taken from a real patient, a real practice or a real dataset, or
derived from one. The generator is deterministic, so a regenerated copy is the same data, not
similar data.

It is one of three cards built on the same generator and the same schema. The shared material —
why the structured tables and the free-text documents are deliberately not redundant, why the
data is identifying on purpose, why `access.mode: gateway` is load-bearing, what each table holds
and which column descriptions earn their length — is written once, in
`datasets/cypressbay-digestive-health/README.md`, and applies here unchanged with `cbdh_` read as
`rep_`.

## The gaps are in the forms, not in the care

This is the distinction the whole corpus rests on, and it is worth being exact about.

Every examination in this network had a bowel preparation, had a withdrawal time, and earned a
surveillance interval from the same guideline function the other two networks use. The scope
either reached the cecum or it did not, and the record says which. What is missing is the part a
person had to type: a score, a number of minutes, an interval. And the dictated report is still
in the document register with all three in it — which is precisely why this corpus is worth
reading with an assistant rather than with SQL.

Four consequences, each of which an answer computed off this data has to survive:

- **An adequate-preparation denominator covers about half the colonoscopies.** `bbps_total >= 6`
  selects the examinations somebody scored, not the examinations that were adequately prepared.
  A detection rate computed that way is correct arithmetic over a subset, and an answer that does
  not say which subset is wrong.
- **A mean withdrawal time is a mean over the documented half.** Which is not the same population,
  and is probably not the same population in the way that matters.
- **About a fifth of completed colonoscopies have no recall at all.** No interval in the record
  means no recommendation row, which means no recall row — so those patients are invisible to
  every overdue query this practice runs against its own data. An adherence figure computed from
  `rep_recalls` flatters the practice; the honest denominator is the colonoscopies in
  `rep_procedures`.
- **The most recent quarter is not comparable.** Capture runs two months behind, so a query for
  "the last 90 days" across all three networks reads two thirds of a quarter here and a whole one
  elsewhere.

There is **no flag marking an incompletely captured row.** The null is the flag, and the card's
column descriptions say so in each of the four places — because the card is the only thing a
consuming agent knows about this database, and a gap that is not described there is a gap the
agent will silently compute through.

## Why a network like this is in the set

Because the interesting answer to a pooled question is not the ranking. Three practices that all
score every examination produce three numbers and a winner. One practice that does not produces
an answer that has to state its own coverage — and an assistant that reports the gap instead of
quietly dropping the rows is the behaviour actually worth demonstrating to a clinical audience,
who have all seen the other kind.

Nothing here says rural medicine is worse medicine. It says this network's *registry* is thinner,
which is a documented and very ordinary fact about community practice, and which has a visible
cause in the data: eleven sites and eighteen thousand patients are run on six surveillance
coordinators.

## Generating and loading

```bash
cd generate
./generate.py --out ./out              # 18,000 patients, ~145,000 rows, 44 documents
```

```bash
cd out
CH_URL=http://10.10.1.11:8123 CH_USER=<owner> CH_PASSWORD=<secret> ./load.sh
```

The schema drops and recreates every table, so a reload replaces the corpus rather than doubling
it. The documents under `notes/` are uploaded to the application by hand.

Checks:

```bash
cd ../../gi-network-generator
./selftest.py --network ridgeline      # asserts each declared rate against what the corpus has
./selftest.py --all-networks           # after any change to the shared generator
```

The self-test checks the rates in the table above against the corpus, not just that they are
non-zero: a knob that quietly halved would still leave gaps, and would take the cross-network
comparison with it. It also checks that a missing preparation score never drags a clinical column
down with it — the care is not missing, only the form.

## Access

Restricted. Synthetic demonstration data: it may be loaded, queried and shown freely, and it
carries no patient confidentiality obligation because there is no patient. It is not a substitute
for real data in any evaluation that claims clinical validity.

The reader account behind this card's secrets must be `readonly = 2`, not `readonly = 1`, for the
reason set out at the end of `datasets/cypressbay-digestive-health/README.md`.
